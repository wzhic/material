# 最小治理与关键确认边界-ADR-0002

## 状态

已接受，2026-08-21；决策人：用户；关联需求：治理精简-REQ-0004；关联任务：GOV-0003。

## 上下文

仓库早期治理为首次根信任、跨平台摘要和 CI 故障建立了签名、scope/code 回执、Run 导入和多层恢复合同。这些历史记录有审计价值，但继续要求唯一维护者为普通编辑、联网、依赖、push 和 CI 回写反复介入，维护成本超过了日常风险收益。用户要求进一步精简，并允许任务创建有记录的子 Agent 和子任务。

## 考虑的方案

1. 保留原有逐阶段审批与 GitHub 同步：机器绑定最密，但用户成为流程操作员，普通任务等待和故障面过多。
2. 取消全部治理：操作最少，但无法保护任务范围、受保护记录、验证真实性和 multi 发布边界。
3. 采用最小治理：普通可逆工作自主完成，只在关键风险和最终动作确认，同时保留范围、真实验证、非强制 Git、子任务记录和三平台 CI。

## 决策

采用方案 3。

- 清晰需求就是普通可逆工作的范围决定，不要求 scope/code 回执。
- 必要联网、常规依赖、范围内编辑、测试、同范围返工、精确提交、功能分支 push、PR 准备和有记录的子 Agent 可由 Codex 直接执行。
- 只有验证豁免、破坏性/不可逆操作、个人或敏感数据、显著安全风险、实质成本、不兼容迁移、最终合并/部署/发布由用户决定。
- 子任务只记录父任务、名称、目的、状态、时间和结果摘要，不记录提示词、内部推理或秘密。
- GitHub Actions 在 PR 与 main 三平台复验并直接展示结果；Codex 负责核对并报告，不要求用户发 Run 链接、提供本地读取 Token、导入 CI 状态或亲自承担日常 CI 核对。

## 后果

正面后果是普通工作可以连续完成、用户介入点清晰、子任务可并行且可追溯，CI 故障不再与本地任务状态形成复杂双向同步。

保留的约束是一个功能一个任务/分支/PR、任务外写入与受保护记录直编禁止、不安全 Git 禁止、本地验证必须真实执行、CI 必须绿色、multi 发布单元分别验收与回退。Actions 页面是 CI 事实来源，Codex 负责核对并向用户报告；用户只承担最终合并决定，因此本地任务不会声称自动同步了远端结果。

## 重新评估触发条件

- 出现因最小门禁导致的范围外写入、错误发布或证据丢失；
- 团队人数、权限、合规或供应链风险显著上升；
- 引入自动部署、生产写入、付费资源或更高敏感等级数据；
- GitHub 分支保护无法稳定执行必需检查；
- 子任务记录不足以重建责任与结果。

重新评估时新增 ADR 替代本文，不直接恢复全部历史协议，也不删除过去任务和回执。
