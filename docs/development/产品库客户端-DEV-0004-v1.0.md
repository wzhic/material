# 产品库客户端-DEV-0004-v1.0

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 关联需求 | `产品库-REQ-0003-v1.0` |
| 关联任务 | `APP-0006`（本地核心）、`APP-0031`（游戏联网补全）、`APP-0034`（表单布局修复） |
| 实现范围 | 产品库本地核心纵向切片 |
| 发布单元 | macOS、Windows 共享业务代码；本任务仅在 macOS 进行本地打包验证 |

## 2. 目标与边界

本工作包实现不依赖模型或外部服务的产品库本地核心：产品列表、搜索、行业筛选、详情、服饰与游戏表单、编辑、删除、重复候选、游戏版本/渠道/组合上下文、产品快照，以及新建分析中的可选单产品绑定。

APP-0006 本地核心工作包不实现模型、素材解析、报告、分析记录、产品合并、批量、云同步、导入导出、数据库应用层加密或客户端发布。游戏联网补全已由独立 `APP-0031` 接入可替换的 Bangumi 公共搜索适配器、按服务合同授权和表单候选回填，详见 [游戏产品联网补全-DEV-0023-v1.0](游戏产品联网补全-DEV-0023-v1.0.md)；它不改变产品只能由用户主动保存创建的边界。

## 3. 分层结构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 领域合同 | `apps/desktop/src/product/types.ts` | 产品、游戏上下文、快照和 IPC 结果类型 |
| 领域规则 | `apps/desktop/src/product/domain.ts` | 必填、安全上限、Unicode 规范化、搜索文本和引用完整性 |
| SQLite 仓储 | `apps/desktop/src/product/repository.ts` | schema、事务、CRUD、重复候选、写入冲突、删除和快照 |
| 主进程边界 | `apps/desktop/src/product/ipc.ts` | 白名单 IPC、错误归一化、不可用降级 |
| preload | `apps/desktop/src/preload.ts` | 向 renderer 暴露窄化 `products` API |
| UI | `apps/desktop/src/ui/ProductLibraryPage.tsx` | 列表、表单、详情、重复提醒、删除确认和恢复状态 |

renderer 保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，不能直接读取 SQLite 或应用数据目录。IPC 失败只返回有限错误码和用户可理解的消息，不返回堆栈、SQL 或绝对路径。

## 4. 本地数据模型

数据库文件为系统 `userData` 目录下的 `material-products.sqlite3`。首次运行创建 `user_version = 1`：

| 表 | 内容与不变量 |
| --- | --- |
| `products` | 稳定 ID、行业、名称、服饰类别、版本化详情 JSON、搜索文本、写入版本和时间 |
| `game_versions` | 游戏内容版本；随基础游戏删除 |
| `game_channels` | 可能影响内容的渠道环境；随基础游戏删除 |
| `game_contexts` | 只保存实际存在的版本或渠道差异；至少引用一个维度 |
| `product_tombstones` | 删除后只保留 ID、行业、删除时间和最后写入版本，不保留产品正文 |

服饰只要求产品名称和服饰类别；游戏只要求游戏名称。选填信息由版本化详情对象承载，当前 UI 提供产品团队维护的推荐分组和补充说明，不提供任意 key/value 编辑器。

## 5. 写入、并发与删除

- 创建、编辑和删除使用 `BEGIN IMMEDIATE` 事务；失败整体回滚。
- 编辑和删除必须提供上次读取的 `writeVersion`。版本不匹配时拒绝过期写入并要求刷新。
- 更新游戏时，同一事务重建该产品的从属上下文；领域校验先阻止孤立引用、重复维度和空差异。
- 删除版本或渠道的表单操作会计算受影响组合，用户确认后同步移除草稿中的依赖组合。
- 删除基础产品会级联删除正文和从属表，再保存最小 tombstone；当前尚未接入报告，因此引用数语义为“不适用”。
- 数据库可读但不可写时允许读取；写操作返回明确的只读恢复提示。数据库完全无法打开时客户端仍启动，产品库展示可重试错误。

## 6. 搜索、重复候选与快照

- 名称与可检索文本在写入时做 NFKC、空白和大小写规范化；`LIKE` 通配符按普通字符转义。
- 服饰重复候选使用同一行业内“规范化名称 + 规范化服饰类别”；游戏使用规范化名称。
- 重复结果只提醒，用户可以查看候选、返回修改或明确继续保存；数据库不建立业务唯一约束，也不自动合并。
- 快照合同 `schemaVersion = 1`，包含产品写入版本、自包含正文、游戏上下文和可选选择结果；生成后是普通值对象，源产品后续编辑不会改写它。

## 7. UI 状态与恢复

- 产品列表区分库为空、筛选无结果、加载、读取失败和正常列表。
- 新建与编辑使用完整页面；首次保存后行业锁定。切换新建草稿行业、取消脏表单、删除产品或删除被组合引用的维度均要求确认。
- 产品库列表、详情、维护和表单共用内容滚动容器；切换子视图后必须回到顶部。长表单的标题与取消/保存操作区使用完全不透明的吸顶层、横向覆盖内容区并以边线和阴影区分正文，滚动字段不得透出或覆盖操作区。
- 保存失败保留全部表单；重复候选提醒不改变正式数据。
- 游戏联网补全在未授权、关闭、离线、超时、限流、无结果或服务故障时只降级补全区，不阻断手填和保存；候选只回填空字段。
- 新建分析按行业展示可选产品；不绑定仍是默认值，产品删除后当前无效选择会被清空。

## 8. 安全与载荷边界

- 本地核心不存素材、API Key、个人数据、凭据或分析报告。APP-0031 只有在用户选择一次或持续允许后才联网发送当前游戏名称，不发送产品库其他内容。
- V1 访问边界是操作系统用户与应用数据目录权限，不宣称 SQLite 应用层静态加密。
- 名称、选填字段、从属项和总 JSON 载荷有宽松安全上限；超限明确拒绝，不静默截断，也不把安全上限解释为永久字段限制。
- 搜索授权只持久化非秘密的供应商版本与发送字段合同；没有项目共享搜索密钥。未来引入用户凭据、其他发送字段或应用层加密时仍需另立任务并提供迁移与回退。

## 9. 验证与证据

任务验证由 `taskctl run-required APP-0006` 执行固定 argv，覆盖文档、仓库静态核对、Lint、TypeScript、Vitest、Electron 打包和治理回归。产品测试覆盖：

- 服饰与游戏最小必填；
- Unicode 规范化和搜索通配符转义；
- 游戏版本、渠道与组合引用；
- 重复候选但允许独立创建；
- 乐观并发冲突；
- 事务删除和列表不可见；
- 版本化、自包含快照。
- 产品子视图切换后共享滚动容器归零；打包客户端长表单滚动时页头不透底，标题与取消/保存按钮保持可见可操作。

本工作包的 macOS 打包成功和应用启动不能替代 Windows 真机安装、升级、只读目录和恢复验收。10,000 条性能、备份恢复、迁移中断和旧客户端打开新 schema 也必须在后续持久化治理工作包补验。

## 10. 回退与后续工作

当前为首次新建产品库 schema，没有既有业务数据迁移。代码回退可撤销 APP-0006 内容提交；若用户已经主动创建产品，回退前保留数据库文件，不能删除或覆盖。旧代码不会识别产品库文件，但也不应修改它。

后续不依赖模型的建议顺序：

1. 产品库备份、恢复、schema 升级与 10,000 条性能验证；
2. 分析记录 SQLite schema、确认保存和本地检索；
3. 本地媒体元数据、指纹与文件重定位恢复；
4. PDF 导出和 macOS / Windows 平台验收；
5. 在目标网络与 Windows 安装包中复验 APP-0031 的真实联网可达性；若更换搜索服务，保持适配层和重新授权边界。
