# 子任务协作-DEV-0002-v1.0

## 目的

定义轻量的子 Agent 与子任务审计合同。创建子 Agent 不需要用户逐次审批，但必须在开始前通过 `taskctl` 记录名称、目的和状态，结束后补充结果。

## 记录边界

- 记录：父任务、子任务名称、目的、状态、开始时间、结束时间和结果摘要。
- 不记录：提示词、内部推理、凭据、密钥、原始隐私数据或无关工具日志。
- 子 Agent 只能在父任务允许范围内工作；最终结果由主 Agent 复核并通过统一验证。

## 事实来源

子任务动态状态只保存在父任务的 `subtasks` 记录中，并通过 `taskctl current`、`subtask-start` 和 `subtask-finish` 读取或更新。父任务由外层任务记录天然确定；本文不复制“当前子任务”表，避免名称、时间和状态与机器记录漂移。

## 状态定义

- `in_progress`：子任务已分派，尚未回收最终结果。
- `completed`：结果已由主 Agent 回收并纳入统一验证。
- `failed`：子任务未形成可用结果，主 Agent 需要返工或重新分派。
- `cancelled`：主 Agent 主动停止，必须记录原因。
