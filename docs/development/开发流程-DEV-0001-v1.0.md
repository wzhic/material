## 开工

1. 把一个可独立验收的功能记录为一个任务，写清目标、范围/非范围、允许路径、依赖、验证和回退。
2. 使用一个独立的 `codex/...` 分支；第二个独立功能使用另一个任务、分支和 PR。
3. 用户的清晰需求就是普通可逆工作的范围决定。任务进入 `IN_PROGRESS` 后，Codex 在范围内连续实现，不再逐项索取 scope 或 code 确认。
4. 有会改变结果的实质歧义、个人/敏感数据、显著安全风险、实质成本、不兼容迁移或不可逆结果时，用人话列明影响并停下让用户决定。

`project-control/tasks/**`、`project-control/reviews/**` 和 `project-control/current-task.json` 只能由控制工具写入。命令参数以工具 `--help` 为准，不手工伪造状态或验证结果。

## 范围内自主工作

`IN_PROGRESS` 内，以下可逆动作不需要用户逐项确认：

- 创建、编辑、重命名和整理允许路径内文件；
- 必要联网、查阅资料、运行官方生成器和安装常规依赖；
- 采用有回退方式的技术默认值；
- 运行测试、修复同范围失败、整理文档；
- 精确提交、非强制推送功能分支和准备 PR；
- 创建有记录的子 Agent 或子任务。

发现需要修改任务外路径、夹带第二个功能或改变数据/安全/成本/兼容/不可逆边界时，不先改文件；使用新任务或受控范围修订。

## 子 Agent 与子任务

可按文档、Hook、工具、测试等独立工作面分派子 Agent，不需要用户逐次批准。创建前记录父任务、名称、目的、状态和开始时间，回收后记录结束时间与结果摘要；具体边界与迁移记录见 [子任务协作-DEV-0002-v1.0](子任务协作-DEV-0002-v1.0.md)。

不记录提示词、内部推理、凭据、密钥、原始隐私数据或无关工具日志。子 Agent 继承父任务范围，不能自行扩大需求；主 Agent 负责复核内容、处理冲突和运行统一验证。

## 脚手架与依赖

- 应用初始化先检查目标目录，使用官方生成器或可信脚手架，不手写依赖清单假装生成结果。
- 普通常规依赖属于可逆技术选择，Codex 可在任务范围内安装；记录用途、版本锁定、许可证/维护风险和移除方式。
- 涉及显著成本、敏感数据外传、重大安全边界或不兼容迁移的依赖必须先让用户决定。
- 生成缓存、虚拟环境、构建产物和嵌套 Git 不进入仓库。

## 实现与注释

- 命名使用易读、统一的业务词汇，避免堆叠内部术语和无必要抽象。
- 注释只解释原因、不变量、兼容要求、安全边界和前后置条件，不复述代码。
- 变更历史放在任务、Git 和 ADR，不写在代码注释中。
- 共享客户端代码明确平台适配边界；持久化变更必须有 schema 版本、迁移、备份和回退/前滚方案。

## 验证

本地检查由 `taskctl run-validation` 或 `run-required` 按任务声明的 argv、超时和发布单元真实执行。失败、未运行、超时、空测试集或环境缺失不是通过；不得修改测试掩盖失败、降低阈值或自行豁免。

PR 和 `main` 由 GitHub Actions 在 Linux、macOS、Windows 上通过同一受控入口复验。Actions 页面直接展示结果，不要求用户发送 Run 链接、提供读取 Token 或把 CI 状态抄回本地。Windows 治理 runner 不能替代真实 Windows 产品验收。

## 提交、PR 与等待

- 提交只包含当前任务的精确文件清单，信息包含需求/任务编号和易读摘要。
- 禁止 force push、`--no-verify`、历史改写、隐藏失败和清理其他任务/用户文件。
- 功能分支 push 和 PR 准备是普通工作，不单独确认；最终合并、部署和发布由用户决定。
- 已提交任务等待 CI 时可切换到下一独立任务，不要求先把 Actions 元数据导入本地。
- CI 失败时保留事实，在同一功能分支追加同范围修复并完整重跑；范围变化使用新任务。

## 多发布单元与回退

macOS、Windows 和 backend 分别维护版本、自动验证、真实环境验收和回退条件。跨单元需求记录 API、文件格式、身份、SQLite schema 的兼容矩阵及部署/回退顺序。无依赖阻断且数据兼容时可单独回退；存在不兼容或不可逆点时使用协调回退或前滚修复。

## 完成条件

范围内实现与文档齐全、受控本地验证通过、GitHub CI 绿色、发布单元兼容与回退条件明确后，任务可以提交最终决定材料。验证豁免、破坏性/不可逆操作、敏感数据或显著安全/成本/不兼容迁移，以及最终合并、部署、发布仍须用户明确决定。
