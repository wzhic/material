# 治理总则-GOV-0001-v1.0

## 目的

项目治理用于确保工作有范围、有记录、可验证、可回退，不用于让用户逐项批准日常操作。现行普通任务策略见 [治理精简-GOV-0004-v1.0](治理精简-GOV-0004-v1.0.md)。

## 项目边界

项目为 `M + multi`：一个 monorepo，包含共享业务代码的 macOS/Windows 客户端与统一后端三个独立发布单元。三者分别构建、验收、版本、发布和回退；跨单元变化记录兼容矩阵与顺序。

## 角色

| 角色 | 职责 |
| --- | --- |
| 用户 | 给出需求；决定验证豁免、破坏性/不可逆操作、高影响数据/安全/成本/不兼容迁移，以及最终合并、部署、发布 |
| Codex | 拆分任务、记录范围、实现可逆工作、管理子任务、实际验证、准备提交/PR并如实报告 |
| GitHub Actions | 在独立三平台 runner 重跑当前任务声明的检查并展示结果 |

用户的清晰需求就是普通可逆工作的范围决定。Codex 不代替用户做上述关键决定，也不把普通联网、依赖、编辑、测试、功能分支 push、PR 准备或子 Agent 创建升级为审批点。

## 最小记录

- 需求：使用者、目标、范围/非范围、流程、数据与安全、异常恢复、兼容回退、验收、验证、假设与未决事项。
- 任务：独立功能、分支、允许路径、依赖、验证、回退和状态。
- 子任务：父任务、名称、目的、状态、开始/结束时间和结果摘要。
- 决策：影响多个需求或长期维护的背景、选项、结论、后果和复查条件。
- Git 与 CI：文件历史、精确提交和提交后复验结果。

不在代码注释中维护变更历史；注释只说明原因、不变量、兼容要求和前后置条件。子任务记录不保存提示词、内部推理、秘密、原始隐私数据或无关日志。

## 工具职责

- `SessionStart` 只提供当前任务、状态、分支、允许路径、阻断项、未完成子任务和下一步。
- `PreToolUse` 只拦任务外写入、受保护记录直编、不安全 Git、错误分支和冻结阶段写入。
- `taskctl` 管理任务/子任务并运行受控验证。
- `reviewctl` 记录关键用户决定，不服务普通编辑审批。
- `reconcile` 核对文件、任务、分支、文档和验证事实，不静默修复。

`project-control/tasks/**`、`project-control/reviews/**` 和 `project-control/current-task.json` 是受保护机器记录，只能由控制工具写入。Hook 是 Codex 工具调用边界，不是操作系统安全沙箱。

## 工作与验证

一个独立功能使用一个任务、一个 `codex/...` 分支和一个 PR。`IN_PROGRESS` 内的可逆编辑、必要联网、常规依赖、测试、同范围返工和有记录的子 Agent 可连续执行。范围变化使用新任务或受控修订，不能夹带第二个功能。

本地必需验证只能由 `taskctl run-validation` 或 `run-required` 实际执行。失败、未运行、超时和环境缺失不是通过；验证豁免必须由用户决定并显示为 `WAIVED`。GitHub Actions 在 PR 与 `main` 上重跑检查并直接展示结果，不要求用户发 Run 链接、配置本地读取 Token 或导入 CI 元数据。

## Git 与最终动作

提交使用当前任务的精确文件清单，push 只允许非强制快进；禁止 force push、`--no-verify`、改测试掩盖失败或删除门禁。CI 等待期间可切换到下一独立任务。

范围内实现与文档完成、本地验证通过、CI 绿色和兼容/回退条件明确后，停在最终用户决定点。未经用户批准，不执行最终合并、部署或发布。

## 历史兼容

早期 G0 的签名迁移、scope/code 回执、Run 导入和恢复链保留在任务、审核与 Git 历史中用于审计，但不再作为新普通任务的操作步骤。历史 `GOV-0001-R003` 建立了 `conversation-v1` 与 `record-conversation` 迁移边界；该对话回执不是密码学身份或人在场证明。读取旧记录需要保持兼容；不得为简化而删除或改写历史。
