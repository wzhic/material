# 验证与豁免-GOV-0003-v1.0

## 结果定义

- `PASS`：任务声明的检查在指定对象和环境真实执行并成功。
- `FAIL`：检查已执行但失败或结果不满足预期。
- `BLOCKED`：依赖、环境、权限或未决事项使检查无法完成。
- `WAIVED`：用户明确接受未执行检查的风险；它不是通过。

未运行、超时、取消、环境缺失和空测试集都不能记为 `PASS`。调用者不能自报成功；本地结果只由 `taskctl run-validation` 或 `run-required` 的受控 runner 根据真实进程结果派生。

## 分层验证

| 层级 | 证明内容 | 主要证据 |
| --- | --- | --- |
| 治理单测 | 任务、范围、记录和失败关闭规则 | 命令、退出码、输出摘要 |
| Hook 契约测试 | SessionStart 与 PreToolUse 输入输出和允许/拒绝边界 | 测试结果与脱敏失败原因 |
| `reconcile` | 文件、分支、任务、文档和验证事实一致 | JSON 报告与退出码 |
| 应用单元/集成 | 业务实现和依赖边界 | 任务声明的命令与报告 |
| 平台行为 | macOS/Windows 安装、升级、卸载和功能 | 真实目标系统与产物摘要 |
| 数据/发布 | 迁移、持久化、恢复和目标环境行为 | 前后状态、监控和回退检查 |

进程健康、UI 选中状态、夹具数据或治理 runner 不能单独证明真实业务与持久化行为。Windows CI job 绿色也不能替代真实 Windows 客户端验收。

## 本地验证

任务开始前声明检查 argv、超时和覆盖发布单元。受控 runner 使用固定参数真实执行，并记录开始/结束、退出码或超时、环境、输出摘要和被测对象；不得保存秘密或个人数据。

工作区、范围或声明检查发生变化时，相关结果失效并重跑。同范围失败可修复后重新执行；不得删测试、降阈值、改名为通过或复用另一个提交的绿色结果。

## GitHub Actions

PR 和 `main` push 在 Linux、macOS、Windows runner 上，通过唯一受控入口运行当前任务针对 `backend`、`mac`、`win` 声明的检查。workflow 不使用 `continue-on-error` 跳过必需检查，同一分支新提交可以取消旧运行以控制成本。

Actions 页面直接展示提交后验证结果。Codex 核对并报告当前 PR 的必需检查；普通流程不要求用户发送 Run ID/URL、提供仓库外读取 Token、把 CI 元数据回写本地任务或亲自承担日常 CI 核对。检查失败则回到当前功能的同范围修复与重跑；用户只在必需检查绿色后决定是否最终合并。

## 豁免

只有用户可以决定验证豁免。提出豁免时必须用人话说明：

- 无法执行的检查与环境；
- 原因、影响范围和最坏可能后果；
- 已尝试方案与替代证据；
- 有效期和补验触发条件。

用户明确同意后，`reviewctl` 记录绑定任务、检查、对象、环境、原因和有效期的 `validation_waiver`。豁免只作用于列明检查，不扩大文件或需求范围；对象、范围、风险或有效期变化后失效。报告与 PR 必须显示 `WAIVED`，不能显示为 `PASS`。

## 失败与恢复

验证失败先保留事实并定位最早受影响面。同范围问题在当前功能分支追加修复并重跑；范围变化新建任务或受控修订；不可逆恢复、删除历史、强制覆盖和生产操作必须先取得用户决定。任何恢复都禁止 force push、`--no-verify`、删除失败记录或手工改写任务状态。

## 历史说明

G0 的签名迁移、GitHub Run 同步与多次跨平台恢复记录继续留在既有任务、回执和 Git 历史中。它们用于解释过去证据，不再是普通任务必须照做的流程，也不应继续堆入现行排障说明。
