## 用途与使用者

产品服务于广告素材制作者与广告优化师，用于素材制作相关工作。产品不会自动投放广告，也不会自动调整广告预算。

当前已完成应用框架初始化；具体业务流程、素材类型、协作方式和输出渠道仍需按独立需求定义，不得从项目名称推断并提前实现。

## 规模与项目形态

项目正式判定为 `M + multi`：

- `M`：存在公网后端、登录鉴权、本地个人数据、SQLite schema 演进、跨平台发布和三个回退边界。
- `multi`：macOS 客户端、Windows 客户端和统一后端服务可独立构建、发布和回退。
- 代码组织采用一个 monorepo，便于单人维护共享约束和兼容矩阵。

如果未来出现支付、自动投放/预算操作、监管或高度敏感数据、严格高可用、不可恢复操作，或账号越权会造成重大损失，必须暂停并重新评估是否升级为 `L`。

## 发布单元

| 发布单元 | 代码关系 | 运行位置 | 数据边界 | 发布与回退 |
| --- | --- | --- | --- | --- |
| macOS 客户端 | 与 Windows 共享业务代码 | 用户本地 | 个人数据存于本地 SQLite；凭据使用系统安全存储 | 独立构建、签名、版本、发布、回退 |
| Windows 客户端 | 与 macOS 共享业务代码 | 用户本地 | 个人数据存于本地 SQLite；凭据使用系统安全存储 | 独立构建、签名、版本、发布、回退 |
| 后端服务 | 客户端共同依赖 | 公网 | 不保存账号数据；其他服务端数据范围未决 | 独立部署、版本、回退 |

客户端业务功能必须一致，但“共享代码”不等于“一次验证”。两个操作系统的安装、升级、卸载、权限、文件路径、安全存储和运行行为分别验收；`windows-latest` 治理 CI 不能替代真实 Windows 产品验收。

## 环境与分发

- 客户端运行环境：本地。
- 后端运行环境：公网；开发、测试、预发布和生产的具体划分未决。
- 暂不考虑应用商店上架，但技术方案不得封死 macOS 签名/公证、Windows 签名/安装包和未来商店分发能力。

## 身份与数据边界

- 产品涉及登录和鉴权，但身份提供方、会话模型、账号归属和恢复流程未决。
- 后端不保存账号数据。任何后续方案若需要后端持久化账号、身份映射或凭据，均属于边界变化，必须重新审核。
- 个人数据保存在本地 SQLite；字段清单、敏感等级、加密、备份、删除、导出和保留期限未决。
- 登录令牌、密码、私钥和密钥不得明文写入 SQLite、日志、Git 或任务记录。

## 维护约束

- 预计维护人数为 1 人，因此流程需要自动化、可复现、低维护成本，但不能用人少作为跳过审核和验证的理由。
- 用户决定验证豁免、破坏性/不可逆操作、高影响数据/安全/成本/不兼容迁移和最终合并/部署/发布；清晰需求范围内的普通可逆工作由 Codex 连续完成。
- 需求、任务、Git 和决策记录维护变更历史。代码注释只解释原因、不变量、兼容要求和前后置条件。

## 治理信任边界

- 历史 OpenSSH 与对话回执迁移保留用于审计，但新普通任务不要求 scope/code 回执或私钥操作。
- GitHub Actions 在 PR 与 `main` 三平台复验并直接展示结果；普通流程不要求用户发送 Run 链接、提供读取 Token 或把 CI 状态写回本地。
- Hook 只覆盖它实际接管的 Codex 调用，不覆盖程序子进程、外部终端或未接入路径；任务范围、受控 runner、CI、非强制 Git 和最终用户决定共同构成流程约束。
- 多发布单元任务按 `mac`、`win`、`backend` 逐一绑定自动验证、兼容、发布和回退证据，不能用单个聚合结论替代。

## 当前限制

风险最坏后果评估被用户延期。该延期不阻断纯治理、应用框架和低风险可逆本地工作，但不能据此降低个人数据、安全、成本、不兼容迁移、不可逆操作或发布边界；进入相关产品需求前必须重新确认。

任务 GOV-0003 引入 [治理精简-GOV-0004](../governance/治理精简-GOV-0004-v1.0.md)：清晰需求即普通范围决定，联网、常规依赖、范围内编辑/测试、功能分支 push、PR 准备和有记录的子 Agent 不逐项确认；真实验证、任务边界、受保护记录、不安全 Git 与最终用户决定仍保留。历史 G0/GOV-0002 证据继续留在任务和 Git 中，不再写成日常操作步骤。
