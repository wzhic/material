# 需求文档

每个需求使用独立目录和版本化主文档。目录格式为 `<需求名>-<REQ-ID>/`，主文档格式为 `<需求名>-<REQ-ID>-v<major.minor>.md`。

- 当前需求：[治理基线-REQ-0001](治理基线-REQ-0001/治理基线-REQ-0001-v1.0.md)
- 新需求起草：[需求文档模板-REQ-TEMPLATE-0001-v1.0.md](需求文档模板-REQ-TEMPLATE-0001-v1.0.md)

需求变化必须递增版本并重新核对审核回执。范围、数据、安全、成本、兼容或不可逆后果发生变化时，旧回执自动失效，禁止继续实现。

待审核或已批准的主文档必须完整保留模板的 24 个默认章节，且每节非空；不适用项写明理由和确认依据。UI 需求必须有用户流程图与交互状态，非 UI 需求使用合适的状态图、时序图或数据流图，并补充文字。假设和未决事项清单不得省略，具体文档不能保留模板“待填”占位。
