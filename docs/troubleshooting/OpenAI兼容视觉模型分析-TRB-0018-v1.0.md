# OpenAI兼容视觉模型分析-TRB-0018-v1.0

## 1. 适用范围与安全原则

本文用于排查 `APP-0028` 的 OpenAI 兼容视觉配置、M02 代表帧读取、主进程 JPEG 准备、Chat Completions 图片内容块、证据绑定和对话重新分析。模型凭据与端点先参照[模型连接与凭据-TRB-0007-v1.0](模型连接与凭据-TRB-0007-v1.0.md)，M02 与临时产物先参照[确定性媒体解析-TRB-0006-v1.0](确定性媒体解析-TRB-0006-v1.0.md)和[工具执行底座-TRB-0005-v1.0](工具执行底座-TRB-0005-v1.0.md)。

排障不得输出或保存 API Key、Authorization Header、图片 Base64 / data URL、原始图片、视频、音频、绝对路径、临时路径、Prompt、模型原始响应或供应商错误正文。诊断只使用配置 ID、Provider / 模型 ID、视觉开关、帧数量、尺寸、字节计数、证据 ID、时间、稳定错误码和阶段。

不得通过关闭视觉门禁、放宽路径校验、读取任意文件、持久化临时帧、增加自动重试、切换模型、把图片送进 renderer、关闭 TLS或日志打印请求体来“修复”。

## 2. 现象、原因与安全恢复

| 现象 | 可能原因 | 安全恢复 |
| --- | --- | --- |
| 配置弹窗没有视觉开关 | Provider 只声明文本能力，例如固定 DeepSeek | 使用声明图片能力的 OpenAI 兼容配置；不要篡改配置文件 |
| 已启用视觉但模型选择显示仅文本 | 设置快照过期、保存冲突或旧配置默认关闭 | 重新读取配置；在编辑弹窗显式启用并保存，不自动扩大范围 |
| `/models` 成功但视觉分析失败 | 模型列表不能证明图片能力，具体模型不支持 `image_url` 或 JSON 模式 | 核对供应商官方文档和准确模型 ID；由用户显式改选或关闭视觉 |
| 显示视觉证据准备失败 | M02 失败、产物未注册 / 已释放 / 被替换、图像不可解码或仍超限 | 保留表单，重跑当前素材；先修复 M02 / 临时目录，不读取其他路径替代 |
| 图片较大时失败 | 压缩后仍不能满足单边、单张或总预算 | 使用可读取素材重试；不要提高上限或静默少发未知帧 |
| 视频只分析少量画面 | 设计上只发送最多 8 个 M02 代表帧 | 查看报告“代表帧覆盖”局限；完整视频直传不在 V1 |
| 报告画面结论不足 | 配置未启用视觉、帧未覆盖关键画面、模型证据不足 | 核对模型选项状态和帧时间；用户可通过对话指出时间后重新分析，但不能伪造未发送帧 |
| 模型返回未知证据 | 模型引用了未发送或错误的 evidence ID | 整份输出拒绝；重试同模型或升级 Prompt / Adapter，不放宽证据校验 |
| 视觉请求 400 / 404 / 422 | 供应商内容块、data URL、`detail` 或 JSON 模式兼容不完整 | 使用符合当前合同的端点 / 模型，或新增受控 Adapter；不暴露任意请求编辑器 |
| 视觉请求限流 / 超时 | 账号额度、图片 Token、网络或服务问题 | 显示受影响维度，由用户决定同模型重试；不得自动重发或切换 |
| 取消后仍有临时目录 | 工具进程延迟退出或清理失败 | 先确认调用不再 active，再使用受控 stale sweep；不删除宽泛目录 |
| 对话重新分析提示原素材变化 | 当前素材指纹与首轮不同或会话已释放 | 重新定位相同完整指纹文件，从新建分析重新开始 |
| 历史报告没有视觉原图 | 按设计不保存视觉字节或缩略图 | 使用仍可访问的源素材播放 / 定位；报告只保存证据摘要 |

## 3. 建议诊断顺序

1. 记录运行 ID、配置 ID、Provider、模型 ID、视觉开关、媒体类型、阶段和稳定错误码；禁止复制请求体或路径。
2. 在模型管理确认 Provider 声明图片能力且该配置 `visualInputEnabled=true`。旧配置缺字段应表现为关闭，不应自动升级为开启。
3. 确认配置连接状态为 ready、模型仍在可用列表；`GET /models` 成功只证明列表合同，不证明视觉完成能力。
4. 核对 M01 素材身份与 M02 输出属于当前指纹，帧数为图片 1 / 视频 1～8，时间不越界，产物出现在同一 invocation 的注册列表。
5. 核对读取发生在 invocation 完成后、release 之前；artifact ID 与相对路径唯一匹配，文件大小和真实路径未变化。
6. 只记录压缩后的数量、宽高与字节数：单边 ≤1280、单张 ≤1 MiB、总计 ≤6 MiB。不要记录 Base64。
7. 核对请求只调用用户选择的 `{baseUrl}/chat/completions` 一次，用户消息含 text 与 image_url 内容块；不含原视频、音频、文件路径或远程图片 URL。
8. 若远端成功，继续核对视觉结论引用的 evidence ID 确实属于已发送帧，视频时间合法；失败时不得生成报告或文本回退报告。
9. finally 后核对 invocation 已 release；重新分析只能复用当前内存视觉输入，不再次扩大到其他文件。
10. 修复后运行 APP-0028 固定受控验证；真实供应商、macOS 和 Windows 安装包结果分开记录，不用模拟测试代替。

## 4. 泄漏与临时文件检查

用明确的假 Base64 哨兵和假路径运行成功、失败、取消、报告确认、反馈、重新分析、PDF 和应用重启场景。扫描 renderer 可见对象、SQLite、报告 JSON、PDF、普通日志、模型审计、Tool 审计、任务记录和 Git diff；哨兵命中必须为 0。测试源码内固定假字节属于测试输入，不得使用真实素材或真实 Key。

临时帧只位于 Tool Broker 精确 invocation 工作区。正常运行结束后逐个 release；崩溃遗留由已存在的 24 小时 stale sweep 处理。清理只能解析受控 UUID 与固定目录前缀，拒绝符号链接、非目录和范围外路径。不要手工执行宽泛递归删除，也不要把临时目录复制进诊断包。

## 5. 验证与防复发

回归至少覆盖：Provider / 配置双重门禁、旧配置默认关闭、设置持久化、帧 invocation / artifact 精确读取、release 后拒绝、符号链接和替换文件拒绝、图片 1 / 视频 8 帧边界、1280 像素、1 MiB / 6 MiB 预算、官方内容块、证据 ID / 时间、零原视频音频、零自动重试 / 切换 / 文本回退、错误零字节泄漏、报告与 PDF 零 Base64、对话重新分析内存复用。

Electron package 通过只证明打包和静态依赖可用，不证明 `nativeImage` 能解码所有真实素材。发布前必须在真实 macOS 和 Windows 安装包用固定 JPG、PNG、视频关键帧和损坏样例复验；至少一个用户自有视觉模型需由产品负责人自行判断结果是否可用。任何提高帧数 / 字节、上传原视频音频、引入缓存或代理的方案都扩大数据外发，不能作为普通排障修改。
