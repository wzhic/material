# 产品库本地存储-TRB-0002-v1.0

## 1. 适用范围

本文用于排查 APP-0006/APP-0007 产品库数据库打不开、只读、写入冲突、完整性失败、备份失败、恢复失败和 schema 不兼容。不得通过删除数据库、清空应用数据、修改备份文件名或关闭治理门禁来“修复”。

## 2. 数据与隐私边界

主数据库名为 `material-products.sqlite3`，位于 Electron 的系统 `userData` 目录；备份位于该目录下的应用管理备份区。产品 UI 和普通日志不得显示绝对路径、SQL、产品正文或堆栈；renderer 只能看到备份 ID、类型、创建时间、大小、schema、产品数和校验状态。

备份不是云备份、导出或跨设备迁移格式。产品库不包含素材、API Key 或报告；删除产品也不等于删除既有本地备份或未来报告快照。当前无自动备份删除功能，永久清理需另立需求并明确保留策略。

## 3. 常见现象

| 现象 | 可能原因 | 安全处置 |
| --- | --- | --- |
| 产品库显示“无法打开” | 目录权限、文件损坏、schema 不受当前客户端支持 | 停止写入，保留原文件，核对客户端版本和目录权限 |
| 状态显示只读 | 主库或目录只读、系统权限变化 | 允许查看；恢复权限并重启后再写入或恢复备份 |
| 完整性显示“需要处理” | `quick_check` 未通过 | 停止写入，不新建空库；从已验证备份恢复 |
| 创建备份失败 | 空间不足、目录权限、源库异常 | 主库保持不变；恢复空间或权限后重试 |
| 某个备份显示“校验失败” | 文件损坏、截断或 schema 不兼容 | 不恢复、不改名伪装；保留其他已验证副本 |
| 恢复按钮不可用 | 主库只读、目标损坏或 schema 不兼容 | 先恢复写权限，或选择校验通过的兼容备份 |
| 恢复失败 | 安全备份、暂存复验、原子替换或恢复后复验失败 | 原库会自动回滚；重启后核对状态和产品数再重试 |
| 提示其他窗口已更新 | `writeVersion` 与最新记录不一致 | 刷新产品，基于最新内容重新编辑，不覆盖新版本 |
| 搜索无结果 | 当前筛选、关键词或数据规范化不匹配 | 清空条件；区分库为空与筛选无结果 |
| 新建/编辑页打开后停在中部，或标题与字段重叠 | 产品子视图继承了共享内容区旧滚动位置，或吸顶页头背景/层级失效 | 返回产品列表后重新进入；开发排查应核对视图切换滚动归零与 `.product-form-header` 的不透明背景、边距和层级，不改产品数据 |
| 提示客户端版本过低 | `PRAGMA user_version` 不是当前支持的 v1 | 使用兼容客户端；不得静默降级或重建 |

## 4. 诊断顺序

1. 记录页面显示的有限错误类型、动作时间和数据维护页的 schema、完整性、读写状态、产品数与备份数；不复制产品正文。
2. 判断是否只有写入失败。列表仍可读时按只读故障处理，不执行恢复替换。
3. 检查系统应用数据目录的当前用户权限和磁盘剩余空间。
4. 在数据维护页刷新备份清单，确认目标显示“校验通过”且产品数符合预期。
5. 恢复前保留应用自动创建的安全备份；不得手工覆盖唯一主库或唯一已验证副本。
6. 恢复完成后再次读取状态，并从产品列表核对预期产品。需要写入验证时，新建一条可识别测试产品、读回，再正常删除。

## 5. 正常恢复流程

1. 打开“产品库 → 数据维护”。
2. 选择创建时间和产品数符合预期、显示可用的备份。
3. 阅读替换影响并二次确认。
4. 客户端重新校验目标、自动创建当前库安全备份、同目录暂存、原子替换并复验。
5. 成功后状态应为完整性正常、schema v1、产品数可读；产品列表应对应目标备份时间点。

取消确认时数据零变化。任一步失败时应显示可重试错误，目标备份继续保留；若已经进入替换阶段，客户端回滚原库。恢复成功不会自动删除恢复前安全备份。

## 6. 启动中断与文件边界

恢复替换只操作客户端生成、同目录且带 UUID 的精确临时文件。如果进程在主库改名后中断，下次启动在主库缺失时恢复最新的合法旧库副本；健康主库通过完整性检查后才清理合法临时文件。

不要手工创建、改名、删除 `restore-old` 或 `restore-new` 文件，也不要把任意 SQLite 文件放进备份目录并改成应用文件名。客户端会忽略不符合精确备份合同的普通文件和软链接；手工文件不获得可信备份身份。

## 7. 验证与升级边界

- 权限恢复：重启后列表可读，数据维护页显示可读写，新写入可立即读回。
- 冲突恢复：刷新后看到另一窗口的新内容，重新编辑产生更高写入版本。
- 备份恢复：完整性与 schema 正常，产品数和目标时间点一致，恢复前安全备份可见。
- schema 不兼容：使用兼容的新客户端打开；当前没有 v2 迁移，不执行降级或空库重建。
- 平台边界：macOS 本地测试和打包不能替代 Windows ACL、安装、升级、恢复中断与回退真机验收。

## 8. 仍需独立处理的故障证据

当前自动化已覆盖备份成功、备份损坏、恢复成功、恢复中断启动恢复、分页和 10,000 条性能基线。磁盘满、文件被外部进程长期占用、断电、Windows 权限变化和未来真实 schema 迁移仍需在相应平台/迁移任务中故障注入；没有这些证据时不能宣称跨平台异常恢复完成。
