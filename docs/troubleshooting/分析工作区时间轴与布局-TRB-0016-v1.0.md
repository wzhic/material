# 分析工作区时间轴与布局问题排查 TRB-0016 v1.0

## 1. 排障原则

先区分布局显示问题、播放器时长问题和报告证据问题。布局只保存在当前用户的 Renderer localStorage，时间轴缩放与选择只属于当前页面会话；不得通过修改报告毫秒值、伪造情绪节点、降低证据校验、清空整个应用数据目录或删除分析记录解决 UI 问题。

## 2. 常见现象与安全恢复

| 现象 | 常见原因 | 安全恢复 |
| --- | --- | --- |
| 重启后布局恢复默认 | localStorage 被系统或隐私策略拒绝、被清理或值损坏 | 当前会话继续可用；核对 Renderer 存储权限后重新拖动，不影响报告和数据库 |
| 某一区域无法继续缩小 / 放大 | 已达到导航、媒体或时间轴安全边界 | 属于预期；使用其他分隔线重分配，或点击“恢复默认布局” |
| 分隔线无法拖动 | 指针事件被窗口边缘、系统手势或覆盖层拦截 | 先用 Tab 聚焦分隔线并用方向键验证；关闭覆盖层后重试 |
| 图片工作区没有时间轴 | 图片没有视频时基，V1 明确隐藏视频专属轨道 | 使用图片预览和报告区域证据；不要为图片生成伪时间轴 |
| 播放头不移动 | 视频尚未加载元数据、播放已暂停或源文件不可读 | 等待元数据；确认播放器可播放；历史文件移动时先走安全重新定位 |
| 点击轨道没有证据高亮 | 点击的是空白轨道、画面说明或无证据占位 | 选择具备证据 ID 的镜头、字幕、口播 / 声音片段；空白点击只定位时间 |
| 情绪曲线只有虚线 | 报告没有同时具备时间与强度的可靠情绪证据 | 保留“证据不足”；不得用随机或插值节点伪装结论 |
| 放大后看不到末尾内容 | 时间轴已扩展并保留当前横向滚动位置 | 使用底部 / 系统横向滚动，或点击“适应全片”回到 100% 起点 |
| 刻度、轨道与播放头错位 | 使用了不同宽度、时长或 CSS 缩放 | 核对三者均位于同一 `timeline-tracks` 内容层并共享报告时长；不要改写证据时间补偿 UI |

## 3. 布局存储核对

唯一布局键为 `material.workspace-layout.v1`，正文应只包含 `sidebarWidth`、`mediaPercent`、`timelineHeight` 三个数字。缺失或损坏时客户端恢复默认；越界值在读取时裁剪。该键不应包含素材路径、文件名、报告、用户问题、产品、模型配置或 API Key。

若必须恢复布局，只删除这一个键或使用 UI 的“恢复默认布局”。不要清理整个 localStorage，因为其他功能可能拥有独立设置；不要编辑 SQLite，布局与数据库无关。

## 4. 时间与证据核对

报告媒体时长存在时，轨道证据按报告时长计算；报告未就绪时播放器元数据只用于刻度和播放头。所有定位值应限制在 `0` 到总时长之间。证据片段以 `startMs` 定位，区间宽度由 `endMs` 计算；没有终点时使用最小可见宽度，但不把该显示宽度写回报告。

点击镜头、OCR、口播 / 声音或情绪节点后应同时出现：播放器跳到对应时间、播放头移动、可用证据高亮、对话输入上方出现时间引用。若只有某一项失败，先核对事件是否命中按钮、证据 ID 是否存在和播放器是否已加载，不要重新运行模型作为首选修复。

## 5. 平台验收

macOS 与 Windows 发布单元分别验证：指针拖动三处分隔线；Tab 和方向键调整；当前值播报；安全最小 / 最大值；客户端重启恢复；一键恢复默认；100%～400% 缩放和水平滚动；适应全片；播放 / 拖动进度驱动播放头；轨道与情绪节点定位；图片隐藏时间轴。窗口系统缩放和最小尺寸必须真机检查，Electron 打包通过不能替代这些交互验收。
