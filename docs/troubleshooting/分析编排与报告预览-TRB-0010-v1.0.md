# 分析编排与报告预览-TRB-0010-v1.0

## 1. 适用范围与原则

本文排查 APP-0015 的新建分析启动、主进程媒体编排、产品快照、进度 / 取消 IPC、工作区和待确认报告预览。媒体运行时见[确定性媒体解析-TRB-0006-v1.0](确定性媒体解析-TRB-0006-v1.0.md)，模型配置见[模型连接与凭据-TRB-0007-v1.0](模型连接与凭据-TRB-0007-v1.0.md)，模型输出与融合见[分析运行与融合报告-TRB-0009-v1.0](分析运行与融合报告-TRB-0009-v1.0.md)。

排障不得记录 API Key、本地绝对路径、Prompt 正文、供应商原始响应、临时媒体或内部工具日志；不得用自动切换模型、伪造证据、把抽帧当视觉理解、跳过必要工具或手工写入分析记录来恢复。

## 2. 常见现象与安全恢复

| 现象 | 可能原因 | 安全恢复 |
| --- | --- | --- |
| “开始分析”不可用 | 素材、行业或已验证模型缺失；素材不可用；已有运行尚未终止 | 补齐必填项；在模型设置中验证配置；重新定位同一素材；等待或取消当前运行 |
| 启动后提示素材不可用 | 文件移动、权限丢失、内容 / 大小 / 修改时间变化 | 回配置页重新定位并通过强指纹检查；内容不同则作为新素材重新选择 |
| 绑定产品后立即失败 | 产品已删除、库不可用、行业不一致 | 刷新并重新选择；或明确取消产品绑定后创建新运行，不伪造旧产品快照 |
| 卡在媒体探测 / 结构解析 | FFmpeg / ffprobe 不在可执行路径、媒体损坏、必要工具超时 | 核对运行时和媒体兼容性；修复后由用户显式重试，不跳过 M01 / M02 / 视频 M03 / M05 / M08 |
| 报告缺少字幕、口播或声音 | OCR / ASR / 声音事件模型未配置或执行失败 | 查看报告局限和进度；配置对应本地模型后重试；不把缺失结果解释成素材没有文字 / 口播 / 声音 |
| 有代表帧但画面章节为空 | 当前 DeepSeek 只接收文本证据，代表帧只是采样元数据 | 属于真实能力边界；配置 OCR 可补文字证据，视觉内容需后续支持并验证视觉 Provider |
| 分析失败后没有自动换模型 | 一次运行固定用户选择 | 用户在配置页选择当前模型重试，或显式选择另一已授权模型再启动 |
| 点击取消后短暂仍显示运行中 | AbortSignal 正在等待已启动工具 / 网络调用收口和清理 | 等待取消终态；不要连续启动相同运行 ID。Provider 已收到的请求可能仍产生费用 |
| 进度重复或没有百分比 | 阶段事件会随模型内部阶段更新，且不是时间估算 | 以最新阶段文本为准；相邻完全相同事件会去重，不把事件数换算成剩余时间 |
| 时间轴没有画面 / 标签区间 | 代表帧无语义，报告级标签没有可靠时间证据 | 保持空轨和局限提示；不能为了填满时间轴虚构位置 |
| 生成报告后分析记录仍为空 | APP-0015 只生成内存中的待确认预览 | 属于预期；下一阶段完成确认保存前，关闭应用会丢弃草稿 |
| 报告页面意外返回配置 | 用户导航或 Renderer 状态已重建 | 当前草稿不持久化；若内存仍在可从工作区查看，否则需重新分析 |

## 3. 建议诊断顺序

1. 记录不含秘密的 `clientRunId`、错误码、当前阶段、行业、媒体类型、配置 ID 和模型 ID。
2. 检查素材会话 `sourceStatus`；失效时先恢复同一强指纹素材，不继续调工具或模型。
3. 检查产品库是否可读、产品是否活动且行业一致；产品非必要，可由用户决定取消绑定后重试。
4. 按 M01 → M02 / 视频 M03、M05 → M04 / M06 / M07 → M08 顺序定位。必要能力失败应终止，可选能力失败应出现在局限中。
5. 工具成功后检查 M08 素材身份、时间和 schema；`metadata.frame.sample` 不应进入语义时间线。
6. 进入模型阶段后按 TRB-0009 核对模型审计、严格 JSON、证据引用、目标、评分和标签；失败不重试、不切换。
7. 修复后使用新的 `clientRunId` 创建运行，执行专用单元测试及任务要求的完整验证。

## 4. 取消、清理与恢复边界

取消只影响当前运行，不清除新建分析配置、产品库、模型配置或素材源文件。Tool Broker invocation 无论成功、失败或取消都应进入显式释放；若进程崩溃，下一次启动只清扫严格隔离且超过 24 小时的工具工作区。不要手工删除宽泛临时目录，也不要把临时帧或 WAV复制进应用数据或报告。

必要能力、素材或模型失败后，UI 留在工作区并给出重试入口。可选识别失败仍可生成报告，但必须让用户看到受影响的能力。待确认草稿不是恢复点；应用重启后重新分析属于 V1 预期。正式报告恢复、历史快照和记录删除语义由下一阶段记录集成负责。

## 5. 验证与防复发

修改编排顺序时保留必要 / 可选失败和全部 invocation 释放测试；修改取消时覆盖工具阶段与模型阶段；修改 M08 时保留跨素材、越界帧和“代表帧不产生语义时间线”测试；修改报告 UI 时保留证据不足、空标签、空情绪、图片无时间线和长文本布局。

发行前仍需分别执行 macOS 和 Windows 真机：应用启动、文件权限、FFmpeg / ffprobe 发现、取消、退出清理、模型安全存储、长媒体、中文路径和报告滚动。学习型运行时或视觉 Provider 上线前必须固定来源、版本、hash、许可证、模型条款和卸载 / 回退方案。
