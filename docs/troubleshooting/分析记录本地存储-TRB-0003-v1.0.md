# 分析记录本地存储-TRB-0003-v1.0

## 1. 适用范围

本文用于排查 APP-0008 分析记录库打不开、只读、完整性失败、查询失败、反馈失败、删除失败和 schema 不兼容。不得通过删除数据库、清空应用数据、直接改 SQLite、伪造报告或关闭治理门禁来“修复”。

## 2. 数据和功能边界

数据库名为 `material-analysis-records.sqlite3`，位于 Electron 系统 `userData` 目录。它保存用户确认后的报告快照、必要素材引用、规则/产品/运行摘要、反馈和来源关系，不保存源视频、图片、持久缩略图、API Key、内部 Prompt、推理或工具日志。

当前客户端没有真实报告生产器，因此新装后的空记录库是正常状态。不得为了测试 UI 手工插入演示记录或把未确认预览写入正式库。产品库和分析记录使用独立数据库；分析记录故障不应导致产品库数据被删除或覆盖。

## 3. 常见现象

| 现象 | 可能原因 | 安全处置 |
| --- | --- | --- |
| “尚无已确认的分析记录” | 用户尚未确认保存真实报告 | 正常空状态；等待报告预览能力接入后由用户确认 |
| 当前筛选无结果 | 关键词或组合筛选排除了现有记录 | 清空条件；不要当成库为空或系统失败 |
| 查询失败但仍显示旧结果 | 数据库占用、读取错误或完整性异常 | 保留条件和旧结果，重试；不要据此认为记录已删除 |
| 分析记录模块无法打开 | 目录权限、文件损坏、schema 不受支持 | 停止记录写入，保留原文件，核对客户端和权限 |
| 可以查看但反馈/删除失败 | 数据库或目录只读、空间不足、占用 | 原报告保持不变；恢复权限/空间后重试 |
| 反馈保存失败 | 可信度超出 1～5、内容超限或写入失败 | 修正输入或恢复存储；报告和旧反馈不变 |
| 来源记录已删除 | 重新分析来源被单独删除 | 后续记录仍完整可读；不重新创建或自动改关系 |
| 源素材需重新定位 | 当前只保存引用摘要，或未来检查发现失效 | 报告/反馈继续可用；等待素材句柄能力，不替换为其他文件 |
| 提示客户端版本过低 | `user_version` 不是当前支持的 v1 | 使用兼容客户端，不降级、不重建空库 |

## 4. 诊断顺序

1. 区分空库、无匹配和查询失败三种页面状态，记录动作与有限错误文案，不复制报告正文。
2. 清空筛选并重试；若旧结果仍可见，不执行删除或重建。
3. 确认产品库是否仍正常，避免把两个独立数据库的故障混为一体。
4. 检查系统应用数据目录的当前用户权限、磁盘空间和文件占用。
5. 核对客户端版本与分析记录 `user_version`。未知版本停止使用旧客户端写入。
6. 恢复权限或空间后重启客户端，从列表进入一条既有详情并读回报告；不要用手工 SQL 修改用户记录。

## 5. 写入和删除恢复

- 确认保存：未来接入后必须由主进程一次事务写入并读回；失败返回报告预览，不能出现半条正式记录。
- 反馈：失败时旧反馈和报告正文保持不变；恢复后重新提交。
- 清除反馈：成功只删除反馈，不删除报告或修改素材评分。
- 删除记录：取消或失败时零变化；成功不删除源素材、不级联删除后续重新分析记录。
- 来源关系：来源被删除后保留来源 ID并显示已删除，不能把后续记录误判为损坏。

## 6. 完整性、版本和回退

启动会检查 schema v1 和数据库完整性；失败时模块返回不可用，不创建空库覆盖。当前工作包没有 schema 迁移或记录备份 UI，应用卸载/重装不是恢复方案。发生损坏时保留原库，等待独立备份恢复任务或从已有系统级副本恢复；恢复操作不得覆盖唯一可用副本。

代码回退到不认识分析记录的客户端前保留数据库文件。旧客户端不会显示记录，但不应修改它。未来 schema 变化必须先实现一致备份、迁移失败回滚和旧客户端保护，再执行真实迁移。

## 7. 尚未完成的故障证据

当前自动化覆盖原子保存、无半记录、查询、反馈、非级联删除、敏感字段和 10,000 条性能。仍需独立验证：磁盘满、外部进程长期占用、进程在确认事务中被终止、真实备份恢复、Windows ACL、Windows 安装升级，以及素材移动后的指纹重定位。没有这些证据时不能宣称完整跨平台恢复闭环。
