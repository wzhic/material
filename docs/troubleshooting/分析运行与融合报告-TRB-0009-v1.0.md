# 分析运行与融合报告-TRB-0009-v1.0

## 1. 适用范围与原则

本文排查 APP-0014 的证据包、版本化 Prompt、模型单次运行、模型输出校验和融合报告草稿。媒体解析与 EvidenceSchema 问题参照[确定性媒体解析-TRB-0006-v1.0](确定性媒体解析-TRB-0006-v1.0.md)，模型配置、Key 和 Provider 问题参照[模型连接与凭据-TRB-0007-v1.0](模型连接与凭据-TRB-0007-v1.0.md)，规则、标签和评分问题参照[规则包加载与评分-TRB-0008-v1.0](规则包加载与评分-TRB-0008-v1.0.md)。

排障不得记录 API Key、Prompt 正文、供应商原始响应、素材全文或本地路径；不得通过删除严格校验、伪造证据、把证据不足计为 0、自动重试 / 切换模型或把未确认草稿写入分析记录来恢复。

## 2. 常见现象、原因与恢复

| 现象 | 可能原因 | 安全恢复 |
| --- | --- | --- |
| 分析在模型调用前提示没有证据 | M01～M08 没有产生任何可验证 OCR、ASR、音频或结构证据 | 查看媒体解析局限，修复对应工具后创建新运行；不要调用模型生成无依据内容 |
| 证据身份或时间无效 | 素材在解析中变化、媒体类型不一致、时间超出当前时间轴 | 重新解析同一指纹素材；素材已变则作为新素材启动 |
| 报告显示证据被抽样 / 截断 | 证据数量、单条文本或包大小超过工程安全上限 | 这是可见降级；核对遗漏数量，必要时优化上游证据聚合后重新运行，不提高上限掩盖问题 |
| 模型调用失败后没有换模型 | 设计要求一次运行固定配置与模型 | 由用户在 UI 中选择重试，或显式选择另一个已授权模型后创建新运行 |
| 返回内容看似 JSON 但仍拒绝 | 含 Markdown、未知 / 缺失字段、错误 schema 或越界文本 | 对照版本化输出合同修正 Provider / Prompt；不从正文正则截取“像 JSON”的片段 |
| 提示未知证据 | 模型引用未发送、被抽样丢弃、其他运行或自造的 ID | 只引用本次证据包 ID；没有依据的结论移除或标记证据不足 |
| 某维度证据类型不相容 | 例如只用音频事件证明商品视觉呈现 | 改用规则声明类型的真实证据；没有相容证据时返回 `insufficient_evidence` |
| 图片输出被拒绝 | 生成了声音结论、视频时间点或视频目标 | 使用图片合同，声音数组留空、情绪时间为 `null`，只引用图片区域证据 |
| 游戏 / 服饰目标被拒绝 | 游戏使用购买目标，或服饰使用拉新 / 拉活 | 服饰固定购买转化；游戏按素材证据返回拉新、拉活或 `unclear` |
| 固定 / 动态标签拒绝 | 固定 ID 未定义或重复，动态标签覆盖固定定义、重复或无证据 | 使用当次规则快照 ID；合并同义动态标签并补当前证据 |
| 总分为空但有维度分 | 已评分适用权重低于规则覆盖门槛 | 展示覆盖率和证据不足；补证据后新建运行，不把缺失维度记 0 |
| 调用成功但配置 / 模型身份不一致 | Provider、服务或调用方改变了用户显式选择 | 整次失败，核对模型服务审计；不得接受替代模型结果 |
| 取消后仍出现模型账单 | 请求可能已到供应商，取消只能尽力终止传输 / 等待 | 保留取消审计并检查 Provider 行为；不能把取消报告保存，也不能自动再次调用 |
| 模型成功但没有分析记录 | APP-0014 只生成待确认草稿 | 属于预期；后续 UI 和保存任务完成前不能把草稿手工写入记录库 |

## 3. 建议诊断顺序

1. 先记录运行 ID、错误码、行业、媒体类型、规则 / Prompt 版本、配置 ID、模型 ID 和阶段；不记录 Key、Prompt 或供应商正文。
2. `EVIDENCE_INVALID` 先运行 EvidenceSchema 与媒体归一化测试，确认素材指纹、证据唯一 ID、时间 / 区域和来源版本。
3. `MODEL_FAILED` 核对模型审计状态、配置写版本、Provider、模型、超时和稳定错误码；确认一次运行只有一次调用。
4. `MODEL_OUTPUT_INVALID` 用合成脱敏响应跑严格解析器，依次核对 JSON、根字段、目标、证据 ID / 类型、图片 / 视频边界、标签、维度和诊断引用。
5. `RULE_FAILED` 核对当前行业 / 媒体显式启用的规则快照，不跨模板回退。
6. 修复后创建新运行，执行分析引擎专用测试、桌面端 lint、typecheck、全部普通测试、package、文档和治理回归。

## 4. 验证与防复发

每次修改 Prompt 或输出合同都必须提升版本，并保留：Markdown 拒绝、未知字段、未知证据、提示注入数据边界、目标隔离、图片时间 / 声音、维度证据类型、标签冲突、单次模型调用、取消和原始响应不泄露测试。每次修改证据包上限或抽样方式都要验证确定性、首尾覆盖、遗漏可见和输入大小。

日志与分析结果只能存安全摘要。上线新 Provider 前，应使用同一固定证据集验证模型身份不变、失败不重试、结构化输出、超时取消和中国大陆网络可达性；支持原图、抽帧或视频输入必须在 Provider 能力中明确声明并用真实素材验证，不能沿用当前文本能力的结论。
