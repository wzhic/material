# 历史记录源素材恢复问题排查 TRB-0014 v1.0

## 1. 记录显示“需重新定位”

1. 报告、反馈和 PDF 仍应正常工作；不要把素材不可用误报为报告损坏。
2. 旧记录在 v3 之前没有持久访问句柄，首次打开显示需重新定位是预期行为。
3. 新记录出现该状态时，检查源文件是否移动、删除、离线或失去系统权限，并检查 Electron `safeStorage` 是否可用。
4. 点击“重新定位”并选择原文件；客户端必须重新计算完整 SHA-256，不能只按名称或大小恢复。

不得为了恢复播放把明文路径写入 SQLite、日志、报告或 Renderer，也不得扫描目录猜测同名文件。

## 2. 重新定位提示“文件不匹配”

- 核对候选的媒体类型和大小，再确认文件是否经过重新编码、裁剪、覆盖或内容替换；即使文件名相同，只要完整指纹不同就必须拒绝。
- 不匹配不会替换旧密文引用、不会改写报告证据，也不会产生重新分析记录。
- 若用户确实要分析新文件，应从“新建分析”创建新任务，不能把旧报告绑定到新素材。

## 3. 源文件存在但无法自动恢复

1. 关闭占用文件的外部程序后重试，检查磁盘、移动硬盘或网络卷是否已经挂载。
2. macOS 检查当前应用是否仍有该目录访问权限；Windows 检查当前用户是否有读取权限。
3. 系统安全存储不可用或密文无法解密时，应用只返回“需重新定位”，不回显密文、原路径或底层安全存储错误。
4. 通过系统选择器重新选择同一文件；成功后新的路径会重新加密并替换旧引用。

当前非 App Store 沙箱构建没有安全作用域书签。若未来启用 macOS App Store 沙箱后跨重启权限失效，应实现并迁移书签合同，不得关闭沙箱或放宽全盘权限。

## 4. 播放器或证据定位不可用

- 先确认详情的素材状态为“可用”，并且播放器或图片预览已完成加载。
- 视频证据只有 `startMs` 不为空时提供定位按钮；点击后只移动播放头，不重新运行模型。
- 图片记录没有视频时间轴；恢复后显示原图，区域证据定位仍以已保存报告能力为限。
- 离开详情会释放短生命周期会话；从详情创建重新分析时会把同一已验证会话移交给新草稿。
- 若协议读取期间文件再次变化，停止播放并重新打开详情或重新定位，不能继续把旧证据指向变化后的文件。

## 5. schema v3 迁移失败

1. 保留原数据库和备份，不手工修改 `PRAGMA user_version`。
2. 检查应用数据目录写权限和磁盘空间；迁移使用独立事务，失败应回滚引用表创建。
3. 使用 `PRAGMA quick_check(1)` 和 `PRAGMA foreign_key_check` 核对结构；不要通过删除记录表或关闭外键解决。
4. 旧客户端只理解 v2；回退代码前恢复兼容备份，不能让旧代码直接写 v3。

## 6. 安全核对

- SQLite 中只能出现 Base64 密文引用，不能出现可搜索的绝对路径片段。
- Renderer、报告、PDF、日志、任务记录和错误消息都不应出现绝对路径或密文。
- 删除记录后，对应 `analysis_record_sources` 行应由外键级联移除，源文件保持原样。
- 不通过关闭 `safeStorage`、保存明文、返回 `file://` URL 或开放任意文件读取 IPC 处理故障。
