# 对话分析与重新分析-TRB-0012-v1.0

## 1. 适用范围

本文排查 `APP-0021` 的分析中对话、时间引用、待确认报告反馈、当前会话多版预览和从历史记录重新分析。媒体解析、模型连接、报告确认和 SQLite 的底层问题分别参见本目录的 `TRB-0006`、`TRB-0007`、`TRB-0010` 和 `TRB-0011`。

## 2. 快速判定

| 现象 | 先检查 | 预期恢复 |
| --- | --- | --- |
| 提交关注点后没有立即出现新报告 | 初次媒体解析是否仍在运行 | 关注点进入队列；初版成功后明确显示重新分析阶段 |
| 报告反馈提交后失败 | 报告页错误、模型配置、网络状态 | 旧预览保持可读和可确认；修复后再次提交 |
| 提示原分析会话不可用 | 应用是否重启、来源上下文是否超过内存缓存上限 | 从当前配置重新开始；V1 不恢复未确认会话 |
| 时间轴引用被拒绝 | 引用时间和素材时长 | 清除无效引用或重新选择可靠片段 |
| 历史记录无法重新分析 | 记录是否有指纹、所选文件是否为原文件 | 重新选择指纹一致文件；不匹配时零变化 |
| 草稿没有自动带出模型 | 原模型配置是否仍存在且连接可用 | 用户显式选择配置；系统不得自动换模型 |
| 草稿没有绑定原产品 | 原产品是否已删除或行业是否变化 | 显示警告并由用户选择；不复用陈旧快照作为当前产品 |
| 新记录没有来源关系 | 是否从记录详情进入、确认前是否取消了关联 | 重新从来源记录创建草稿；不要手改 SQLite |

## 3. 证据核对顺序

1. 在分析工作区查看“分析进度”最后一个阶段；重新分析应出现 `applying_guidance` 或模型生成阶段。
2. 确认旧预览是否仍能打开；失败时旧预览丢失属于缺陷。
3. 查看当前所选模型显示名和模型标识；同一次细化不得静默变化。
4. 从记录详情发起时，确认文件选择器返回的素材指纹与记录一致。
5. 只有用户点击“确认并保存”后才检查分析记录数量和来源关系。

不得把 API Key、内部提示词、完整工具日志或原素材复制进排障记录。

## 4. 常见恢复

### 4.1 解析中提交关注点

初次媒体解析运行中可以提交关注点，但不会改变正在执行的 Tool 参数。系统先完成当前解析，再复用其归一化证据调用所选模型生成新版。若初次解析失败，排队关注点保留在当前页面消息中，但不会绕过必要媒体能力直接调用模型；使用当前配置重试。

### 4.2 重新分析失败或取消

模型错误、网络超时或用户取消只终止当前重新分析运行。最近一次成功预览应恢复为可操作状态，正式记录数不变。不要删除旧预览来伪装恢复成功，也不要自动改用另一个模型。

### 4.3 来源上下文过期

运行时只保留有界的当前进程上下文。应用重启、缓存淘汰或来源标识无效时，增量重新分析会被拒绝。返回新建分析配置，使用同一素材和所需配置重新开始；这属于 V1 的明确恢复路径。

### 4.4 素材变化

当前会话重新分析前会再次检查素材状态和 SHA-256。文件被移动、替换或失去权限时停止模型调用。历史记录重新分析由用户重新选择文件；不匹配的候选会立即释放，不能把旧证据关联到新文件。

### 4.5 原模型或产品失效

历史草稿只在原模型配置和当前产品都可匹配时预填。缺失项留空并显示警告。用户选择新的模型后，它是一次新的显式运行；原记录仍展示确认时的旧模型和产品快照。

### 4.6 确认保存失败

确认失败时保留最新报告、旧预览、可见对话和来源记录关系。修复本地存储或来源记录状态后重试。同一个报告确认标识重复提交必须幂等；不同内容复用同一确认标识应返回冲突。

## 5. 修复验证

- 类型检查通过，不能以缺少依赖或跳过检查替代。
- 针对性测试证明重新分析没有再次调用媒体 Tool，且沿用来源模型和产品快照。
- 失败 / 取消测试证明最近成功预览可恢复、记录数不变。
- 记录仓库测试证明可见对话、来源关系和非级联删除可读。
- macOS 与 Windows 受控验证都通过后，才可把跨平台实现记为本地验证完成。

若修复涉及自动模型切换、持久化未确认草稿、素材复制、PDF、schema 不兼容迁移或删除既有记录，应停止并拆分新的任务或请求对应关键决定。
