# 报告确认与分析记录接线-TRB-0011-v1.0

## 1. 适用范围与原则

本文排查 APP-0017 的报告确认、幂等保存、分析记录 SQLite v2 迁移、成功后详情跳转和未评分显示。报告生成问题先见[分析编排与报告预览-TRB-0010-v1.0](分析编排与报告预览-TRB-0010-v1.0.md)，记录查询、反馈和删除见[分析记录本地存储-TRB-0003-v1.0](分析记录本地存储-TRB-0003-v1.0.md)。

排障不得手工向 SQLite 插入报告、把空分改成 0、删除数据库、修改 `user_version`、复制 API Key / Prompt / 绝对路径到日志，或通过禁用校验和 IPC sender 检查来“恢复”。保存失败必须保留预览并修复根因后重试。

## 2. 常见现象与安全恢复

| 现象 | 可能原因 | 安全恢复 |
| --- | --- | --- |
| 点击确认后仍在预览页 | 数据校验、磁盘、权限、数据库或读回失败 | 阅读页面错误；保留预览，恢复写权限 / 空间或数据库可用性后重试 |
| 连续点击只出现一条记录 | 同一 `draftId` 命中幂等确认 | 预期行为；打开返回的同一记录，不创建副本 |
| 提示“已用不同内容确认” | 同一确认标识被不同快照复用，可能是状态污染或篡改 | 保留现有记录和当前预览；重新运行分析生成新草稿，不覆盖旧记录 |
| 报告显示未评分 | 规则覆盖率不足，`total=null` | 预期行为；查看局限和维度状态，不把未评分解释为 0 分 |
| 保存成功后源素材显示需重新定位 | 记录保存了强指纹但当前阶段没有持久 OS 访问句柄 | 报告仍可查看；历史播放和同指纹重新定位等待后续工作包，不手工保存绝对路径 |
| 保存成功但列表没有停在新记录 | 详情读取失败、组件状态重建或记录库暂不可读 | 进入“分析记录”按素材名检索；若不存在则按原预览重试，不能假定保存成功 |
| 分析记录库提示升级失败 | v1 到 v2 重建、复制或外键检查失败 | 停止写入并保留原库；恢复磁盘 / 权限，从备份副本验证后再启动新版客户端 |
| 旧库只读时能看不能保存 | v1 只读库无法执行事务迁移 | 修复应用数据目录写权限并重启；不要手工修改 schema |
| 应用在“正在保存”时被强制结束 | 进程被杀或系统异常 | SQLite 事务应提交整条或回滚；重启后检索，存在则查看，不存在则重新分析并确认 |
| 新记录出现 0 分但预览是未评分 | 映射或 schema 回归 | 停止继续保存，保留样例；运行 confirmation / repository 测试并核对 `total_score` 可空约束 |

## 3. 建议诊断顺序

1. 保留当前待确认预览，不离开页面；只记录不含秘密的 `draftId`、错误码、媒体类型和时间。
2. 在分析记录中搜索素材名，判断该 `draftId` 是否已经成功保存；重复确认应返回同一记录。
3. 核对应用数据目录可写、磁盘空间和 SQLite 完整性；不得打开数据库后手工写表。
4. 若为迁移问题，核对 `user_version`、表结构和外键检查的只读结果；优先在副本验证恢复，保留原库。
5. 若为输入问题，运行草稿映射与 RecordValidation 测试，检查证据引用、时间范围、分数状态和敏感字段扫描。
6. 若为 IPC 问题，确认调用来自当前 BrowserWindow；不扩大 sender 白名单。
7. 修复后在原预览重试一次，验证成功跳转详情、列表仅一条、内容与预览一致。

## 4. 数据恢复与回退边界

确认保存是单条事务，不存在需要人工拼接的“半条报告”。事务失败后应保持记录数不变；成功返回以主进程读回为准。迁移失败应保留 v1 原数据，不能通过删除库重建来掩盖问题。

代码回退前保留应用数据备份。v2 库含 `confirmation_id` 和可空 `total_score`，旧客户端不具备写入合同，不能直接对同一数据目录降级写入。源素材始终留在原位置，删除 / 恢复分析记录不应触碰素材文件。

## 5. 防复发检查

- 草稿映射测试必须断言不含 Prompt、会话令牌、预览 URL和绝对路径。
- Repository 测试必须覆盖幂等返回、不同内容冲突、无效证据零写入、未评分保真和 v1 迁移。
- IPC 测试必须覆盖非受信 sender 在 Repository 前被拒绝。
- UI 回归必须覆盖保存中防重复 / 防离开、失败保留预览、成功详情和未评分显示。
- 发行前分别在 macOS、Windows 验证首次建库、旧库升级、磁盘满、只读、强制退出和重启检索。
