# 模型连接与凭据-TRB-0007-v1.0

## 1. 适用范围与安全原则

本文用于排查 `APP-0012` 的 DeepSeek 固定 Provider、`APP-0016` 的自定义 OpenAI 兼容 Bearer API，以及 `APP-0020` 的官方 OpenAI 固定 Provider和显式“测试调用”。覆盖 URL 归一化、模型发现 / 手填合并、Electron `safeStorage`、`GET /models`、官方 OpenAI `POST /responses`、DeepSeek / 自定义 `POST /chat/completions` 和“模型管理”状态。工具执行问题参照 [工具执行底座-TRB-0005-v1.0](工具执行底座-TRB-0005-v1.0.md)，媒体解析问题参照 [确定性媒体解析-TRB-0006-v1.0](确定性媒体解析-TRB-0006-v1.0.md)。

排障不得回显或复制 API Key、Authorization Header、密文信封原文、模型 Prompt / 回复、供应商错误正文、绝对敏感文件路径或内部推理。普通日志也不记录完整自定义 URL；需要用户核对时只在受控设置页显示规范化地址，对外截图或工单应再隐藏私有主机和路径。诊断使用配置 ID、Provider ID、模型 ID、连接状态、安全错误码、耗时和系统安全存储后端。

不得关闭 `safeStorage`，不得改成明文文件 / SQLite / 环境变量长期保存，不得跟随重定向、关闭 TLS 校验、放宽 URL 规则、增加任意 Header、自动切换模型、静默重试、用 completion 代替保存 / 刷新模型验证、把窄测试操作改成任意 Prompt IPC、无限延长 30 / 60 秒超时，或删除密文信封“重置”。

## 2. 常见现象、原因与安全恢复

| 现象 | 可能原因 | 安全恢复 |
| --- | --- | --- |
| 显示“系统安全存储不可用” | macOS Keychain 锁定或拒绝、Windows 用户凭据环境异常、Linux 无 Secret Service、应用未 ready | 恢复当前操作系统账户的安全存储后重启应用；不切换到明文或 `basic_text` |
| 新建 / 编辑提示输入无效 | 名称为空 / 过长、Key 含空白 / 控制字符、Provider 不存在，或自定义地址 / 模型 ID 缺失 | 只修正弹窗字段；官方 OpenAI Key 不要求 `sk-` 前缀，不要在日志中打印失败输入 |
| 自定义地址提示协议不允许 | 远端使用 HTTP，或使用 `file:` 等非 HTTP(S) 协议 | 远端改用 HTTPS；HTTP 只允许精确的 `127.0.0.1`、`localhost` 或 `::1` 回环地址 |
| 本地服务用 HTTP 仍被拒绝 | 地址是 `0.0.0.0`、局域网 IP、容器名或看似本机的其他域名 | 改为服务实际监听且受支持的回环主机；不要把远端地址伪装成本机 |
| 地址提示含不支持内容 | URL 含用户名 / 密码、query 或 hash，例如把 Key 放进 URL | 删除这些部分；Key 只填 API Key 字段并由 Bearer Header 发送 |
| 输入完整 completion URL 后出现重复路径 | 未按末尾 `/chat/completions` 识别，或供应商路径不符合兼容约定 | 在设置页重新核对规范化地址；支持 `…/v1` 或 `…/v1/chat/completions`，二者应归一到同一 Base URL |
| 模型列表请求被重定向 | 网关、登录页、区域路由或地址拼写返回 3xx | 找到供应商直接且可信的最终 API Base URL 后重新填写；应用不会跟随跳转并转发 Bearer Key |
| HTTPS 证书错误 | 证书过期、自签名、主机名不匹配或中间代理替换证书 | 修复服务证书或受信网络；不关闭证书校验。仅本机回环开发服务可明确使用 HTTP |
| 保存后连接失败但配置仍存在 | 本地安全保存成功，随后 DNS、代理、TLS、网络、重定向或供应商不可达 | 配置和密文应保留；编辑地址 / Key 后重试，或点击“刷新模型”，不要删除信封 |
| 保存或刷新后没有“测试回复” | 保存、保存后验证和“刷新模型”按设计只调用 `GET /models`，completion 数量为 0 | 这是预期边界；只有 ready 且有效配置内首选模型存在后，用户接受可能少量费用并另行点击“测试调用”才发生成请求 |
| 鉴权失败 | Key 错误、已删除、已轮换、账号权限变化，或端点并非 Bearer 兼容 | 在编辑弹窗输入新 Key 并保存验证；旧 Key 不回显。非 Bearer 接口首版不支持 |
| 余额不足 / 请求过多 | 显式测试调用或未来分析 completion 暴露额度 / 限流；`429` 归一为限流 / 账号额度类错误 | 用户自行处理供应商账号并再次显式操作；项目不代付、不换共享 Key、不产生第二次完成调用 |
| 模型列表为空 / 无效 | `/models` 不存在、返回非兼容结构、模型暂时下线或响应超限 | 状态保持失败，核对 Base URL 和供应商文档；首版不允许分别填写另一个模型列表地址，也不伪造默认模型 |
| 手填模型未出现在可用列表 | 首次 `GET /models` 失败，或表单模型 ID 未成功保存 | 先恢复列表验证并重试；失败时 `manualModelId` 会保留，但不会伪装成已验证的 `availableModels` |
| 手填模型与发现列表重复 | `/models` 返回了相同模型 ID | 成功刷新后按精确 ID 去重，只保留一个选项；不要改名制造第二个模型 |
| 刷新后原选择清空 | 配置 / Key / 地址 / 手填模型变化使旧能力失效，或模型已下线 | 重新验证并显式选择；不自动选择其他配置或模型 |
| 列表验证成功但测试调用失败 | `/models` 不能证明模型调用权限、余额或完成协议；模型级测试状态与配置连接状态独立 | 按 `401` 鉴权、`429` 限流 / 额度、离线 / 网络、服务、60 秒超时或响应无效分类恢复；是否再次测试由用户明确决定 |
| 自定义 completion 返回 404 | Base URL 前缀错误，或第三方完成路径并非 `/chat/completions` | 核对规范化 Base URL；非标准完成路径首版不支持，不能靠任意请求字段绕过 |
| 官方 OpenAI 测试返回 404 或地址异常 | Provider 被错误地走到 `/chat/completions`、官方 Base URL 被覆盖，或模型 ID 不可用 | 官方 `openai` 必须固定 `https://api.openai.com/v1/responses`；检查 Provider / 模型，不允许改地址绕过 |
| “测试调用”按钮不可用 | 配置非 ready、Provider 未注册、安全存储不可用、未设置配置内首选模型，或首选模型不在最近成功快照 | 先按页面说明恢复条件并显式设置配置内首选模型；不要从旧快照或其他配置自动补位 |
| 测试调用长时间加载 | 目标仍在处理或网络无响应 | 最长等待 60 秒；期间按钮禁用且只允许一个在途请求，截止后显示超时，不自动重发 |
| 测试成功但没有回复正文 | 产品只返回成功、Provider / 配置 / 模型、耗时和时间摘要，正文在主进程校验后丢弃 | 这是秘密与最小结果合同；不要为显示正文而放宽 IPC 或记录原始响应 |
| 测试成功但两个模型 ID 不同 | 请求使用配置内首选 requestedModelId，Provider 将 alias 解析为 snapshot 并返回 providerReturnedModelId | 同时保留并显示两个值，提示用户核对；不要互相覆盖，也不要称为客户端自动切换 |
| 模型响应无效 | 响应非兼容 JSON、正文缺失、超过上限或字段类型变化 | 记录 `RESPONSE_INVALID`，升级受控 Adapter 后由用户发起新调用；不保存原始响应 |
| 取消显示为超时或反之 | 调用方取消和内部计时同时发生 | 以先触发的受控状态复验；不要自动重发请求 |
| 密文信封损坏 | 磁盘 / 权限 / 中断写入或外部编辑 | 保留损坏文件并停止模型能力；从用户仍持有的原 Key 重建前先由用户确认，不覆盖未知数据 |
| 删除后配置仍在旧页面 | 页面缓存未刷新 | 重新读取设置快照；主进程已删除则新调用必须返回配置不存在 |
| 提示“配置已变更” | 另一窗口已编辑、刷新或删除同一配置 | 重新读取配置快照后再决定；不使用旧弹窗内容强行覆盖 |
| 回退旧客户端后自定义配置不可用 | 旧版只注册 DeepSeek，不认识 `openai-compatible` 或新增可选字段 | 这是预期降级；不要删除 / 重建密文。重新升级到支持版本后恢复，自定义配置仍须重新核对状态 |
| Windows 可打包但不能保存 Key | CI 只验证共享代码，未覆盖真实 Credential Manager / DPAPI 会话 | 在 Windows x64 真机安装包复验创建、退出重开、更新和删除；不能用 macOS 或打包结果代替 |

## 3. 建议诊断顺序

1. 先确认是固定 `deepseek`、固定 `openai` 还是 `openai-compatible`，记录配置 ID、Provider ID、配置连接状态、模型级测试状态、安全错误码、开始 / 结束时间和耗时；不记录 Key、探测 Prompt、响应正文或完整自定义 URL。
2. 读取系统安全存储状态。不可用时停止，不继续联网、不修改密文文件。
3. 读取设置摘要确认配置存在、Provider 已注册、`writeVersion`、连接状态和最近一次成功模型列表；摘要不应出现 Key 或疑似凭据值。
4. 固定 DeepSeek 不应有可编辑地址；固定 OpenAI 必须使用 `https://api.openai.com/v1`，同样不显示地址或手填模型 ID。只有自定义配置在设置页核对归一化 Base URL 与模型 ID：完整 completion 地址应剥离末尾 `/chat/completions`，并保留 `/v1` 等前缀。
5. 先按协议、远端 HTTPS / 回环 HTTP、无 URL 凭据 / query / hash、拒绝重定向的顺序排除端点策略错误；不要用外部命令把 Key 写入 shell 历史。
6. 点击“刷新模型”。该动作只能执行一次受控 `GET {baseUrl}/models`，按端点、重定向、鉴权、网络、服务或响应无效区分恢复动作，completion 必须为 0。
7. 成功后确认手填模型与发现模型按精确 ID 去重合并，并显式选中手填模型；失败时确认配置 / `manualModelId` 保留、状态为失败、`availableModels` 没有伪造手填项。
8. 若要验证完成能力，先确认配置仍为 ready、系统安全存储可用且 `selectedModelId` 已由用户设置并仍在最近成功列表中；请求 model ID 必须与它一致。页面显示目标、固定非业务探测、不发送素材和可能少量费用；用户点击“测试调用”后最多请求一次，`maxTokens = 128`，60 秒超时。官方 OpenAI 只走 `/responses`，DeepSeek / 自定义只走 `/chat/completions`。
9. 核对模型级加载、成功或安全失败结果：OpenAI 只有 `status=completed`、`error` / `incomplete_details` 为空且输出非空才成功；`401` 为鉴权、`429` 为限流 / 额度、离线为网络、达到 60 秒为超时。成功同时保留 requestedModelId 与 providerReturnedModelId，alias 差异只提示核对，不算客户端切换。任何结果都不显示或记录探测文本、回复正文、Key / Authorization；失败不重试、不换模型，成功不改变配置 ready 或模型快照。
10. 完整分析运行仍是后续独立用户动作；APP-0020 的固定探测 IPC 不能提交业务 Prompt，也不能证明开始分析已经接通。
11. 修复后执行受控的 lint、typecheck、普通测试、模型 runtime 测试、Electron package、文档和治理回归；macOS / Windows 分别做系统安全存储真机测试。不得把 fake server 或本机回环合同测试报告为真实第三方验收。

## 4. 数据外发与费用核对

保存和“刷新模型”会把 Bearer Key 发给对应 Provider 并读取模型列表，但不发送素材、Prompt、报告或 completion。显式“测试调用”会向当次 Provider / 模型发送固定非业务探测文本和最小完成参数，可能产生少量费用，但不发送素材、分析草稿或业务上下文。用户未来开始真实分析后，Prompt、结构化文本证据和业务上下文才会发送到当次选定的第三方或自建端点；APP-0020 尚未接通这条路径。排障人员应让用户核对端点运营方、数据地域、留存 / 训练政策和账号权限，不能由“OpenAI 兼容”推断其隐私保证。

保存 / 刷新模型保持零 completion，但第三方仍可能对 API、账号或流量有自己的计费规则。显式测试和未来分析 completion 由用户的 BYOK 账号承担费用；应用不承诺价格、余额或免费额度，也不会暗中调用、自动重试或切换到另一个模型。

## 5. 验证与防复发

凭据回归使用明确的假哨兵字符串，扫描应用数据、SQLite、报告、日志、导出、任务和提交，命中数必须为 0；测试源码不使用真实 API Key 外形。真实 Key 只从用户明确提供的输入进入短生命周期主进程内存，测试结束不生成凭据产物。

端点回归至少覆盖：Base URL / 完整 completion URL 归一化、`/v1` 前缀、远端 HTTP、三种回环主机、局域网地址、URL 凭据、query、hash、非 HTTP(S) 协议、模型列表和完成重定向、响应大小与超时。保存 / 刷新模型必须断言只有 `GET /models`、零 completion；模型列表测试必须覆盖手填 / 发现合并、精确去重、发现失败不伪造可用模型和首选失效。显式测试必须覆盖官方固定 `/responses`、自定义 `/chat/completions`、ready + 有效 `selectedModelId` 门禁、固定 Prompt、`maxTokens = 128`、单请求、60 秒、`401`、`429`、离线、无效响应和正文禁返。

schema 回归必须用旧 APP-0012 DeepSeek 信封证明 schema v1 缺少 `baseUrl` / `manualModelId` 仍可读，并证明自定义配置往返保存不丢字段。旧版本回退只允许自定义配置不可调用，不能删除、清空或重建其密文；恢复新版本后应能重新读取。

fake contract 使用假 Key 和受控 fetch / 本机服务，只能证明 URL、Bearer、请求体、解析、次数和错误映射。真实 OpenAI smoke 只有同时安全注入 `OPENAI_API_KEY` 与 `MATERIAL_OPENAI_MODEL_ID` 时才运行；任一缺失必须记为 `SKIP`，不能计入 PASS 或由 fake 补位。live 运行不得打印 Key，成功也只证明该账号 / 模型当次可达，不证明完整分析、模型质量或发布验收。

故障恢复不得通过卸载应用、删除安全存储、放宽 IPC sender、暴露任意 Prompt IPC 或关闭 renderer sandbox 实现。生产发布前至少分别验证 macOS Keychain 和 Windows Credential Manager / DPAPI 的首次授权、锁定 / 拒绝、退出重开、Key 轮换与删除；离线时本地页面和历史记录仍可用；供应商不可达不影响产品库和分析记录。当前 Windows x64 真机路径仍未完成，官方 OpenAI 或任何真实自定义第三方端点都不得仅凭 fake contract 宣称验收。
