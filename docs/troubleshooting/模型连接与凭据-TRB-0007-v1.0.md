# 模型连接与凭据-TRB-0007-v1.0

## 1. 适用范围与安全原则

本文用于排查 APP-0012 的模型配置、Electron safeStorage、DeepSeek 动态模型列表、完成调用和设置页。工具执行问题参照 [工具执行底座-TRB-0005-v1.0](工具执行底座-TRB-0005-v1.0.md)，媒体解析问题参照 [确定性媒体解析-TRB-0006-v1.0](确定性媒体解析-TRB-0006-v1.0.md)。

排障不得回显或复制 API Key、Authorization Header、配置文件原文、模型 Prompt / 回复、供应商错误正文、绝对敏感文件路径或内部推理；不得关闭 safeStorage、改成明文文件 / SQLite / 环境变量长期保存、自动切换模型、静默重试、无限延长超时或删除密文信封“重置”。诊断使用配置 ID、供应商 ID、模型 ID、连接状态、安全错误码、耗时和系统安全存储后端。

## 2. 常见现象、原因与恢复

| 现象 | 可能原因 | 安全恢复 |
| --- | --- | --- |
| 显示“系统安全存储不可用” | macOS Keychain 锁定或拒绝、Windows 用户凭据环境异常、Linux 无 Secret Service、应用未 ready | 恢复当前操作系统账户的安全存储后重启应用；不切换到明文或 `basic_text` |
| 新建配置提示输入无效 | 名称为空 / 过长、Key 含空白 / 控制字符、供应商不存在 | 只修正表单值；不要在日志中打印失败输入 |
| 保存后连接失败但配置仍存在 | 本地安全保存成功，随后 DNS、代理、TLS、网络或供应商不可达 | 保留配置和表单上下文，恢复网络后点击“测试并刷新模型”；本地产品和历史记录不受影响 |
| 鉴权失败 | Key 错误、已删除、已轮换或账号权限变化 | 在编辑配置中输入新 Key 并保存验证；旧 Key 不回显 |
| 余额不足 | 用户供应商账号没有可用余额 | 用户自行处理供应商账号后明确重试；项目不代付或切换共享 Key |
| 请求过多 | 供应商返回限流 | 等待后由用户明确重试；不自动换模型或产生第二次费用 |
| 模型列表为空 / 无效 | 供应商响应结构变化、模型暂时下线或返回超限 | 保留为连接错误，核对官方文档和 Adapter 版本；不伪造默认模型 |
| 原选择突然清空 | 配置被删除、Key 更换清空旧能力，或刷新后模型已不在列表 | 用户重新验证并显式选择；不自动选其他配置 |
| 模型响应无效 | 响应非 JSON、正文缺失、超过 4 MiB 或字段类型变化 | 记录 `RESPONSE_INVALID`，升级 Adapter / 业务 schema 后发起新调用；不直接保存原响应 |
| 取消显示为超时或反之 | 调用方取消和内部计时同时发生 | 以先触发的受控状态复验；不要自动重发请求 |
| 密文信封损坏 | 磁盘 / 权限 / 中断写入或外部编辑 | 保留损坏文件，停止模型能力；从用户仍持有的原 Key 重新创建配置前先由用户确认，不覆盖未知数据 |
| 删除后配置仍在旧页面 | 页面缓存未刷新 | 重新读取设置快照；主进程已删除则新调用必须返回配置不存在 |
| 提示“配置已变更” | 另一窗口已编辑、刷新或删除同一配置 | 重新读取配置快照后再决定；不使用旧页面内容强行覆盖 |
| Windows 可打包但不能保存 Key | CI 只验证共享代码，未覆盖真实 Credential Manager / DPAPI 会话 | 在 Windows x64 真机安装包复验创建、退出重开、更新和删除；不能用 macOS 结果代替 |

## 3. 建议诊断顺序

1. 记录配置 ID、Provider ID、连接状态、安全错误码、开始 / 结束时间和耗时；不记录显示名以外的用户输入，也不记录 Key、Prompt 或响应正文。
2. 先读取安全存储状态。不可用时停止，不继续模型联网或修改密文文件。
3. 若安全存储可用，读取设置摘要确认配置存在、Provider 已注册、连接状态和最近模型列表；摘要中不应出现 Key 字段或疑似凭据值。
4. 点击“测试并刷新模型”，按 `AUTHENTICATION_FAILED / BALANCE_INSUFFICIENT / RATE_LIMITED / NETWORK_UNAVAILABLE / SERVICE_UNAVAILABLE / RESPONSE_INVALID` 区分恢复动作。
5. 用专用模型 runtime 测试验证固定 HTTP 合同；需要真实供应商复验时，只使用无素材、无个人信息的最小 Prompt，并确保输出不打印正文和凭据。
6. 修复后执行 lint、typecheck、全部普通测试、模型 runtime 测试、Electron package、文档和治理回归；macOS / Windows 分别做系统安全存储真机测试。

## 4. 验证与防复发

凭据回归使用明确的假哨兵字符串，扫描应用数据、SQLite、报告、日志、导出、任务和提交，命中数必须为 0；测试源码本身也不使用真实 API Key 外形。真实 Key 只从用户明确提供的外部输入进入短生命周期进程内存，测试结束不生成凭据产物。

新增 Provider 必须有固定 HTTPS 域名、重定向拒绝、响应大小限制、动态模型合同、错误脱敏、取消 / 超时、一次调用次数断言和无静默切换测试。修改配置 schema 必须保留旧密文可读或明确停止写入，不能自动清空重建。故障恢复不得通过删除安全存储、卸载应用、放宽 IPC sender、暴露任意 Prompt IPC 或关闭 renderer sandbox 实现。

生产发布前至少分别验证：macOS Keychain 首次授权、锁定、拒绝、退出重开、Key 轮换与删除；Windows Credential Manager / DPAPI 的相同路径；离线时本地页面和历史记录仍可用；供应商不可达不影响产品库和分析记录。
