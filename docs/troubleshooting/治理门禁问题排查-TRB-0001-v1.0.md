# 治理门禁问题排查-TRB-0001-v1.0

## 使用边界

本文处理当前任务、Hook、受控验证、子任务记录和 CI 的常见问题。排障可以读取证据和修复当前任务范围内的可逆问题，但不能借机跳过验证、扩大范围、改写受保护记录、force push、合并、部署或发布。

## 通用顺序

1. 记录现象、当前任务、分支、操作和脱敏错误，不记录密钥或个人数据。
2. 使用 `taskctl current` 与 `reconcile session/static` 核对任务、分支、路径、文档和验证事实。
3. 区分真实规则阻断、工具故障、环境/网络问题和实现失败。
4. 在当前任务范围内修复可逆问题；范围变化使用新任务或受控修订。
5. 通过 `taskctl run-validation` 或 `run-required` 重跑受影响检查，保留失败事实。

`project-control/tasks/**`、`project-control/reviews/**` 和 `project-control/current-task.json` 禁止直接编辑。`reconcile` 只报告，不静默修复。

## SessionStart 内容过长或不准确

- 正常内容只应包含任务 ID/状态、分支、允许路径、阻断项、未完成子任务和下一步。
- 若仍显示旧签名迁移、GitHub Token/Run 同步或完整历史，先确认当前 Hook 已重新加载，再运行 Hook 契约测试。
- 任务损坏或多个活动任务时可以阻断；普通已提交历史、可选回执或等待 CI 不应冻结无关只读工作。

## PreToolUse 拒绝普通操作

- 核对任务是否 `IN_PROGRESS`、实际分支是否正确、目标路径是否在范围内，以及是否触碰受保护记录或冻结阶段。
- 普通只读、必要联网、常规依赖、范围内编辑/测试、功能分支 push、PR 准备和已记录子 Agent 不应因缺少 scope/code 回执被拒绝。
- 如果操作包含任务外写入、force push、`--no-verify`、历史删除或越过最终动作决定，拒绝是预期行为，不拆命令绕过。
- 误拒绝由治理修复任务和回归测试处理，不通过关闭 Hook 临时解决。

## 子 Agent 无记录或无法创建

- 创建前确认当前父任务允许协作，并记录名称、目的、`in_progress` 状态和开始时间。
- 回收后由主 Agent 记录 `completed`、`failed` 或 `cancelled` 及结果摘要。
- 记录缺失时先补事实和原因，再继续汇总；不补写提示词、内部推理、秘密或原始隐私数据。
- 子 Agent 越出父任务路径时丢弃越界改动，保留其他任务/用户内容，并由主 Agent处理冲突。

## 本地验证失败

- 只认受控 runner 的真实执行；失败、未运行、超时、环境缺失和空测试集都不是通过。
- 先修复最早受影响面，再重跑；不得删测试、降低阈值、改失败状态或只展示最后一次绿色。
- 网络或依赖暂时不可用属于可恢复环境问题，可在任务范围内重试必要联网；不能据此自行豁免。
- 必须跳过时停止并说明检查、环境、影响、最坏后果、替代证据、有效期和补验计划，由用户决定是否 `WAIVED`。

## reconcile 报告漂移

- 按报告核对文件、分支、任务、范围、文档和验证对象。
- 不清理其他任务或用户文件来制造干净状态。
- 同范围内容变化使旧验证失效时重跑；范围变化使用新任务或受控修订。
- 可选的普通 scope/code 回执或未导入的 GitHub Run 不应构成新任务阻断；若仍阻断，修复治理合同和测试。

## GitHub Actions 失败

- 直接在当前 PR 或 main 提交的 Actions 页面查看 Linux、macOS、Windows 矩阵结果；不要求用户把 Run 链接发回、提供读取 Token 或把状态抄回本地。
- 每个 job 应通过 `taskctl run-required --phase ci --release-unit <unit>` 唯一受控入口执行任务声明的检查。
- 检查 checkout 的 commit、失败命令、退出码和 runner 环境；在同一功能分支追加修复后重新触发。
- 不使用空提交反复碰运气，不 force push，不把其他提交的绿色结果复用为当前结果。
- Windows 治理 job 只证明治理入口兼容，不能替代真实 Windows 客户端安装、升级、卸载和业务验收。

## LOCAL_VERIFIED 后返工

- 尚未提交的同范围缺陷使用受控 reopen/recovery 使旧结果失效后修改并重跑，不需要用户重复确认。
- 已提交后的同范围 CI 失败在原功能分支追加修复；不得改写已推送历史。
- 允许路径、需求目标、数据/安全/成本/兼容或不可逆边界变化时，建立新任务或受控修订。

## 证据记录模板

| 字段 | 内容要求 |
| --- | --- |
| 问题与任务 | 易读编号和当前任务 |
| 时间/环境/提交 | 可复现定位，不含秘密 |
| 现象与影响 | 区分已见事实与推测 |
| 复现与脱敏证据 | 命令、退出码、摘要 |
| 根因与排除项 | 最早受影响面和证据 |
| 修复与回退 | 精确范围、失败恢复方式 |
| 验证 | 受控 runner 检查与 CI 结果 |
| 防复发 | 测试、文档或合同更新 |

## 禁止操作

不得直接改写任务、回执或当前任务指针，不得关闭 Hook/CI、使用 force push 或 `--no-verify`、删除失败历史、伪造 PASS、暴露敏感信息、清理其他任务内容，或未经用户决定执行验证豁免、破坏性/不可逆操作、最终合并、部署和发布。
